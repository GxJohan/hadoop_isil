Semana 5 y 6 - Hadoop con Docker

Guía paso a paso, desde cero, para levantar Hadoop con Docker dentro del repositorio del curso, subir un archivo CSV de 200 MB a HDFS y comprobarlo en el navegador.

Meta final de la práctica: ver el archivo datos_200mb.csv dentro de la carpeta /data de HDFS en http://localhost:9870. Haz los pasos en orden y no avances hasta cumplir el "Debes ver" de cada paso.

Antes de empezar: lee esto una sola vez

1. Lo que ya debes tener instalado (lo hicimos en clase)

  • Windows: WSL con Ubuntu, Docker Desktop, Git y Visual Studio Code.
  • Mac: Docker Desktop, Git y Visual Studio Code.
  • Docker Desktop abierto y con el motor encendido (ícono de la ballena quieto, sin animación).
En clase ya levantaste Hadoop con cd docker-hadoop y docker compose up -d en otra carpeta. Ahora haremos lo mismo, pero dentro del repositorio del curso hadoop_isil, y además subiremos el archivo de 200 MB.

2. Los comandos se ejecutan en 3 lugares distintos

Cada paso de esta guía tiene una etiqueta de color que te dice dónde se ejecuta. La mayoría de errores vienen de escribir un comando en el lugar equivocado. Mira el inicio de la línea (prompt) para saber dónde estás.

TERMINAL DE TU PC

Windows: la terminal de Ubuntu (WSL) o la terminal de VS Code conectada a WSL.
Mac: la app Terminal o la terminal de VS Code.

Aquí se usan los comandos git, cd, ls y docker.

alumno@pc:~/hadoop_isil$

Entras con docker exec -it namenode bash y sales con exit.

Aquí se usan los comandos hdfs dfs. Aquí no funciona docker.

NAVEGADOR

Chrome, Edge, Firefox o Safari.

Aquí solo miras el resultado en http://localhost:9870. No se escribe ningún comando.

1

Abrir la terminal y verificar Docker

TERMINAL DE TU PC

Antes de todo, confirmamos que Docker responde. Si Docker no funciona, nada de lo demás funcionará.

  1. Abre Docker Desktop y espera a que diga que el motor está corriendo (Engine running).
  2. Abre la terminal: Windows → menú Inicio → Ubuntu. Mac → app Terminal.
  3. Copia y pega estos tres comandos:
Terminal de tu PC 
docker --version
docker compose version
docker ps
Debes ver:
  • Una línea con Docker version ...
  • Una línea con Docker Compose version ...
  • Una tabla que empieza con CONTAINER ID IMAGE ... (puede estar vacía o tener contenedores de la clase: ambas cosas están bien).
Si en Ubuntu (WSL) sale docker: command not found: abre Docker Desktop → Settings → Resources → WSL integration, activa Ubuntu, presiona Apply & restart, cierra Ubuntu y vuelve a abrirlo.

4

Descargar el CSV de 200 MB y ponerlo en hadoop_isil

TERMINAL DE TU PC

Este es el archivo "pesado" que vamos a guardar en Hadoop. Debe quedar en la carpeta raíz hadoop_isil y llamarse exactamente datos_200mb.csv.

  1. Descarga el archivo desde: https://examplefile.com/code/csv/200-mb-csv (quedará en tu carpeta Descargas; el nombre puede ser distinto).
  2. Arrastra el archivo desde Descargas hasta el panel izquierdo de VS Code y suéltalo sobre el espacio vacío de HADOOP_ISIL (no dentro de docker-hadoop).
  3. En VS Code, clic derecho sobre el archivo → Rename → escribe datos_200mb.csv y presiona Enter.
  4. Comprueba en la terminal:
Terminal de tu PC - carpeta hadoop_isil 
ls -lh
Debes ver: una línea con 200M y el nombre datos_200mb.csv, junto a la carpeta docker-hadoop. 
drwxr-xr-x  ...       docker-hadoop
-rw-r--r--  ...  200M  datos_200mb.csv
...
Si no puedes arrastrar el archivo a VS Code:
  • Windows: en la terminal de Ubuntu, estando en hadoop_isil, ejecuta explorer.exe . Se abrirá la carpeta en el Explorador de Windows: arrastra ahí el archivo.
  • Mac: abre la carpeta hadoop_isil en Finder y arrastra ahí el archivo.
Luego cambia el nombre a datos_200mb.csv.
Así debe quedar la carpeta hadoop_isil 
hadoop_isil/

├── datos_200mb.csv       ← paso 4 (200 MB)
├── images/

5

Levantar Hadoop

TERMINAL DE TU PC

Esto es lo mismo que hicimos en clase. Docker crea los contenedores de Hadoop (namenode, datanode, etc.). La primera vez puede tardar varios minutos.

Terminal de tu PC - desde hadoop_isil 
cd docker-hadoop
docker compose up -d
docker ps
Debes ver: en la tabla de docker ps, estos nombres con estado Up: namenode, datanode, resourcemanager, nodemanager, historyserver. En Docker Desktop verás el grupo docker-hadoop con puntos verdes.
Espera 1 minuto antes de seguir. Hadoop necesita un momento para terminar de arrancar.
En Mac es normal ver el aviso AMD64 en Docker Desktop: no es un error.

Contenedores activos en Docker Desktop

Lo que se ve: el grupo docker-hadoop con namenode, datanode, nodemanager e historyserver en verde. Si ves los puntos verdes, Hadoop está corriendo.

6

Comprobar que Hadoop abre en el navegador

NAVEGADOR

Antes de subir el archivo, confirmamos que Hadoop responde.

Escribe esta dirección en el navegador 
http://localhost:9870
Debes ver: una página verde de Hadoop con el título Overview 'namenode:9000' (active).
Si la página no carga: espera 30 segundos y presiona F5. Si sigue sin abrir, vuelve al paso 5 y revisa docker ps.

Pantalla principal del NameNode

Lo que se ve: la pantalla Overview de Hadoop en localhost:9870. Si esta página abre, el NameNode está funcionando.

7

Copiar el CSV de tu PC al contenedor namenode

TERMINAL DE TU PC

Primer viaje del archivo: de tu PC a la carpeta /tmp del contenedor namenode. Volvemos a hadoop_isil porque ahí está el CSV.

Terminal de tu PC - estás en docker-hadoop 
cd ..
docker cp datos_200mb.csv namenode:/tmp/datos_200mb.csv
docker exec namenode ls -lh /tmp/datos_200mb.csv
ComandoQué hace
cd ..Sale de docker-hadoop y vuelve a hadoop_isil, donde está el CSV.
docker cp ...Copia el CSV desde tu PC hacia /tmp dentro del contenedor namenode.
docker exec ... ls -lh ...Revisa, sin entrar al contenedor, que el archivo ya llegó.
Debes ver: quizá el mensaje Successfully copied ... (depende de tu versión de Docker) y luego una línea que termina en /tmp/datos_200mb.csv con tamaño 200M o 201M (ambos están bien).
Si sale no such file or directory: no estás en la carpeta hadoop_isil o el archivo no se llama exactamente datos_200mb.csv. Ejecuta cd ~/hadoop_isil, luego ls -lh, corrige el nombre si hace falta (paso 4) y repite este paso.
8

Entrar al contenedor namenode

TERMINAL DE TU PC → DENTRO DEL CONTENEDOR namenode

Los comandos de HDFS se escriben dentro del contenedor. Este comando te mete en él.

Terminal de tu PC 
docker exec -it namenode bash
Debes ver: el inicio de la línea cambia a algo como root@a1b2c3d4e5f6:/#.
Eso significa que ya estás dentro del contenedor. Desde aquí, los comandos docker no funcionan.
9

Subir el CSV a HDFS

DENTRO DEL CONTENEDOR namenode

Segundo viaje del archivo: de /tmp del contenedor al sistema de archivos de Hadoop (HDFS), en la carpeta /data.

Dentro del contenedor namenode (prompt root@...:/#) 
hdfs dfsadmin -safemode wait
hdfs dfs -mkdir -p /data
hdfs dfs -put -f /tmp/datos_200mb.csv /data/
hdfs dfs -ls -h /data
ComandoQué hace
hdfs dfsadmin -safemode waitEspera a que Hadoop termine de arrancar. Cuando está listo, responde Safe mode is OFF.
hdfs dfs -mkdir -p /dataCrea la carpeta /data dentro de HDFS.
hdfs dfs -put -f ...Sube el CSV a /data. Tarda unos segundos porque son 200 MB.
hdfs dfs -ls -h /dataMuestra lo que hay en /data, con el tamaño en MB.
Debes ver (al final de todo lo que aparece): 
Safe mode is OFF
...
Found 1 items
-rw-r--r--   3 root supergroup    200.1 M ... /data/datos_200mb.csv
Es normal que aparezcan líneas que empiezan con INFO o WARN. No son errores. Lo importante es la última línea con 200.1 M y /data/datos_200mb.csv.
Si sale Name node is in safe mode: Hadoop aún está arrancando. Ejecuta de nuevo hdfs dfsadmin -safemode wait, espera a que diga Safe mode is OFF y repite hdfs dfs -put -f /tmp/datos_200mb.csv /data/

Opcional: mira las primeras líneas del archivo ya guardado en HDFS con hdfs dfs -head /data/datos_200mb.csv

Al terminar, sal del contenedor para volver a la terminal de tu PC:

Dentro del contenedor namenode 
exit
Debes ver: el prompt vuelve a ser el de tu PC (por ejemplo alumno@pc:~/hadoop_isil$).
10

Ver el archivo en localhost:9870

NAVEGADOR

Esta es la comprobación final: ver con tus propios ojos que el archivo está en HDFS.

  1. Abre http://localhost:9870.
  2. En el menú verde de arriba, haz clic en Utilities → Browse the file system.
  3. Verás la carpeta data. Haz clic en ella (o escribe /data en la caja y presiona Go!).

Raíz de HDFS con la carpeta data

Lo que se ve: Browse Directory en la raíz / de HDFS. Aparece la carpeta data.

Archivo dentro de /data (meta final)

Lo que se ve: datos_200mb.csv dentro de /data con tamaño 200.1 MB. Si llegas a esta vista, terminaste la práctica.

Debes ver: en /data, el archivo datos_200mb.csv con Size 200.1 MB y Block Size 128 MB.
¿Qué significa Block Size 128 MB? HDFS no guarda el archivo "entero": lo parte en bloques de 128 MB. Nuestro archivo de 200 MB queda en 2 bloques (128 MB + 72 MB). Así Hadoop puede repartir archivos enormes entre muchas máquinas.
Si no ves el archivo: presiona F5. Si sigue sin aparecer, vuelve al paso 8, entra al contenedor y ejecuta hdfs dfs -ls -h /data. Si ahí tampoco aparece, repite el paso 9.

Checklist final

Terminaste la práctica si puedes marcar todo:

  • docker ps muestra namenode y datanode con estado Up.
  • Dentro del contenedor, hdfs dfs -ls -h /data muestra datos_200mb.csv con 200.1 M.
  • En localhost:9870 → Utilities → Browse the file system → /data se ve datos_200mb.csv.

Apagar Hadoop (cuando termines)

Desde la terminal de tu PC (no dentro del contenedor). El archivo no se borra: la próxima vez que levantes Hadoop, seguirá en /data.

Terminal de tu PC 
cd ~/hadoop_isil/docker-hadoop
docker compose down

Errores comunes

Busca el mensaje que te aparece y aplica la solución.

Me pasa esto Qué hacer
Cannot connect to the Docker daemon Docker Desktop está cerrado. Ábrelo, espera a que diga Engine running y repite el comando.
docker: command not found en Ubuntu (WSL) Docker Desktop → Settings → Resources → WSL integration → activa Ubuntu → Apply & restart. Cierra y abre Ubuntu.
docker: command not found y el prompt es root@...:/# Estás dentro del contenedor. Escribe exit y ejecuta el comando otra vez.
hdfs: command not found Estás en la terminal de tu PC. Primero entra al contenedor con docker exec -it namenode bash (paso 8).
no configuration file provided al hacer docker compose up -d No estás dentro de docker-hadoop. Ejecuta cd ~/hadoop_isil/docker-hadoop y repite.
Conflict. The container name "/namenode" is already in use Hay un Hadoop de la clase anterior todavía creado. Ve a esa carpeta antigua y ejecuta docker compose down, o bórralo desde Docker Desktop (ícono de basura del grupo docker-hadoop). Luego repite el paso 5.
no such file or directory con datos_200mb.csv Ejecuta cd ~/hadoop_isil y ls -lh. Si el archivo tiene otro nombre, renómbralo a datos_200mb.csv (paso 4).
Name node is in safe mode Hadoop todavía está arrancando. Dentro del contenedor ejecuta hdfs dfsadmin -safemode wait y, cuando diga Safe mode is OFF, repite el comando.
localhost:9870 no carga Revisa docker ps: namenode debe estar Up. Espera 30 segundos y presiona F5.
Veo /data vacío en el navegador Presiona F5. Si sigue vacío, repite el paso 9 y revisa que hdfs dfs -ls -h /data muestre el archivo.
code . no abre VS Code Abre VS Code manualmente y usa File → Open Folder para abrir hadoop_isil.

Idea principal

Gracias a Docker levantamos Hadoop sin instalarlo a mano. Luego llevamos un archivo de 200 MB desde nuestra PC hasta HDFS, en dos viajes: PC → contenedor (docker cp) y contenedor → HDFS (hdfs dfs -put).

Hadoop se trabaja con comandos, pero localhost:9870 permite comprobar visualmente que HDFS funciona y que el archivo pesado llegó a /data.
